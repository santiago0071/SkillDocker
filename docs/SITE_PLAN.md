# SkillDocker 官网规划 (SITE_PLAN)

> 最后更新：2026-10-14
> 本文只记录"以后改起来代价很大"的决定。没有写在这里的事，等 Skill 目录有了访问数据再定。

---

## 一、现状

`site/` 是 5 个手写的静态页面：首页、购买页、服务条款、退款政策、隐私政策。部署目标是 Cloudflare Pages，域名 `www.skilldocker.com`。

它现阶段的任务只有两个：通过 Paddle 的域名审核，能收款。在这两件事完成之前，不为下面的规划改动现有页面。

---

## 二、方向

官网以后要承载两类内容：

- **多领域 Skill**：不只面向程序员，覆盖写作、法律、设计、运营等各行各业。
- **多模块 Skill**：几个 Skill 组成的套装（Pack），一次导入一整套工作流。

和别的 Skill 合集的区别在于三点：每个 Skill 带 Skill Doctor 的体检分数；收录前做安全检查；可以一键导入桌面应用。只做"收集"比不过官方库和社区合集。

---

## 三、现在就定下的四件事

### 1. 网址结构

网址被搜索引擎收录、被别人引用之后，再改会丢流量。以下路径现在就保留，不挪作他用：

| 路径 | 用途 |
|---|---|
| `/skills/` | Skill 目录首页 |
| `/skills/<skill-名称>/` | 单个 Skill 的页面 |
| `/skills/domain/<领域>/` | 按领域分类 |
| `/packs/<pack-名称>/` | 多个 Skill 组成的套装 |

现有的 `/buy`、`/terms`、`/refund`、`/privacy` 保持不变。

名称一律用小写英文加连字符，与 Skill 自身的 `name` 字段一致。

### 2. 每个 Skill 的数据格式

每个 Skill 用一个数据文件描述，页面由数据生成，不手写页面。字段：

| 字段 | 说明 |
|---|---|
| 名称 | 与 Skill 的 `name` 一致，同时作为网址的一部分 |
| 一句话说明 | 中英文各一句 |
| 领域 | 取自固定的领域列表，不自由填写 |
| 适用工具 | Claude Code、Codex、Gemini CLI、Antigravity 等 |
| 作者 | 原作者的名字或账号 |
| 来源链接 | 原始出处 |
| 许可证 | 原作品的许可证；没有许可证就如实写"未声明" |
| 托管方式 | 本站托管内容，或只放链接 |
| 体检分数与日期 | Skill Doctor 的结果，以及是哪一天、哪个版本测的 |
| 安全检查结论 | 是否含危险命令、是否有诱导越权的指令，以及检查日期 |
| 收录日期、更新日期 | |

两条硬规则：

- **作者、来源、许可证从第一个 Skill 起就必须填。** 收了几百个之后再补，补不动。
- **许可证不允许转载的，或者没有声明许可证的，只放链接和体检分数，不搬运内容。**

### 3. 中英文用不同的网址

现在的 5 个页面是同一个网址靠按钮切换语言，搜索引擎只会收录默认语言的那一版。Skill 目录要靠搜索带来访问，所以到时候两种语言各有自己的网址：

- `/zh/skills/…`
- `/en/skills/…`

现有 5 个页面在迁移时一并改成这种结构，旧网址跳转到新网址。

### 4. 页面改为自动生成

现在页头页脚在 5 个文件里各写了一遍，改一句措辞要改 5 处。Skill 目录开工时，第一步就是把官网换成"数据加模板生成页面"的方式：

- 仍然是纯静态站，仍然部署在 Cloudflare Pages，不引入服务器端代码。
- 页头、页脚、语言切换只写一处。
- 现有 5 个页面的文字原样迁过去，不借机改内容。

---

## 四、中文用词

中文页面里，"Skill"这个词直接用英文，不要一律翻成"技能"。原因是中文使用者在这个语境下说的就是 Skill，搜索时用的也是这个词。

- 指这类东西本身时用 **Skill**：Skill 目录、Skill 包、写一个 Skill、导入 Skill。
- 产品功能的固定名称保持原样：Skill Doctor、SkillForge。
- "技能"可以在需要解释含义时出现，比如首次介绍时写"Skill（技能）"，之后统一用 Skill。
- 英文页面不受影响。

现状（2026-10-14）：中文文案里"技能"出现 11 次，单独的"Skill"出现 0 次。这条规则适用于以后所有新增的官网文案；现有 5 个页面在下一次改文案时一并调整。

---

## 五、先做最小的一版

官网上线、能收款之后，Skill 目录的第一版只做这些：

1. 按第三节把官网换成自动生成的结构。
2. 收录 20 到 30 个精选 Skill，每个带体检分数、安全检查结论、来源和许可证。
3. 每个 Skill 页面有一个导入入口。

然后看两个数字：有多少人从搜索进来，有多少人点了导入。再决定要不要做下面这些。

---

## 六、现在不定的事

- 投稿和审核流程
- 用户账号
- 评分和评论
- 付费 Skill、作者分成
- 与桌面应用的导入方式的具体实现
- 领域列表的具体内容（开工时再定第一批）

---

## 七、开工前要先想清楚的三个风险

| 风险 | 做法 |
|---|---|
| 版权：别人的 Skill 各有许可证 | 按第三节第 2 条的两条硬规则执行 |
| 安全：Skill 里可以带脚本和指令，等于让 AI 替用户执行别人写的内容 | 收录前必须做安全检查并公开结论；检查不过的不收 |
| 已有官方库和社区合集 | 不比数量，比筛选、体检分数和一键导入 |
